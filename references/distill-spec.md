# 蒸馏规格与证据分级

> 阶段 3 必读。目标是「看完笔记不必再看视频，且每个结论都能回原文核对」。

## 1. 唯一红线

**没有真实文字来源，不蒸馏、不入库。** 真实文字来源指：字幕 / 文稿、本地视频转写稿、在线下载后转写的逐字稿、抖音页面「章节要点」的展开原文。

不属于真实文字来源：单独的视频标题、话题标签、作者其他视频、推荐流文案、SEO 页截断摘要、搜索结果、模型记忆、常识推断。**注意**：作者发布的完整文案（含课程大纲 / 知识点列表）与抖音官方章节要点、总摘要都属于真实文字来源，不要把它们和「标题」混为一谈。

只能拿到元信息时，输出素材卡（见 `assets/note-template.md`）并停止。

## 2. 证据标注（四级 + 平台摘要）

每条要点必须在行首标明等级，不得混用：

| 标记 | 含义 | 要求 |
| --- | --- | --- |
| `【原文】` | 视频里确实说了（**仅逐字稿型**） | 附时间戳或原句锚点；引用单段 ≤150 字；章节型笔记禁用 |
| `【文案】` | 作者发布的文案 / 课程大纲原文或其直接转述 | 注明「作者文案」，不冒充口播原话；型号名、产品名按原词保留，未核实要写明 |
| `【归纳】` | 由多处章节 / 文案合并概括 | 至少列出 2 个来源锚点（章节序号或时间戳）；不得加入原文没有的结论 |
| `【推断】` | 结合业务场景的外推 | 与原文严格分离；写清推断依据；不冒充作者观点 |
| `【平台摘要】` | 抖音平台生成的 AI 章节要点原文 | **只允许出现在「官方章节要点」节（第三节）**；附 `desc` / `detail` / 时间戳；必须注明「平台摘要，非口播逐字稿」；不得当作作者逐字原话引用 |

> 为什么单独给 `【平台摘要】` 一个标记：章节要点是平台对视频的自动摘要，属于真实可核实的文字来源，但不是口播逐字稿。把它标成 `【原文】` 会夸大证据等级，标成 `【推断】` 又会抹掉它的出处价值。

ASR 听写不确定项保留原样，标 `[ASR不确定]`，不猜产品名、数字、人名。数字类信息（价格、比例、时长、年份）未经二次核对不写成确定值。

## 3. 笔记结构

按 `assets/note-template.md` 填充，固定含以下节：

1. **一句话主旨** — `【归纳】`，一句话说清视频在解决什么问题。
2. **内容元信息** — 表格，字段来自 `source/meta.md`；「章节数」写实际条数 + 来源字段，未取得写「未取得」并附审计依据。
3. **官方章节要点**（v1.4 新增，必填） — 来自 `source/chapters.md`：官方总摘要、`# / 时间点 / 章节标题 / 摘要原文` 表、逐条 `【平台摘要】` 原文。节末写与逐字稿时间轴的交叉核对结果。`chapters.json` 的 `count>0` 时此节不得为空、不得写成「未取得」。
4. **核心要点** — 按视频叙述顺序，3–8 条；每条 `标记 + 标题 + 说明 + 出处锚点`。
5. **可执行清单** — 只收能直接照做的动作，标适用条件；没有就写「本条无可直接执行步骤」，不要凑数。
6. **边界与风险** — 作者没说的前提、适用边界、可能的误导；区分「作者明说」与「本笔记补充」。
7. **可迁移点**（旧称「与业务的关联」） — 全部标 `【推断】`，注明是笔记作者的迁移应用，不是视频结论。**场景以使用者的 `_watch/profile.md` 或当次说明为准，不得假定类目/平台/经营方向**；无从判断就写「本条不迁移：与当前场景无交集」。
8. **来源与证据** — 规范 URL、抓取时间、文字来源类型、转写工具、章节来源字段、未取得的元信息字段清单（可审计）。节名统一用「来源与证据」，不用「来源与缺口」。
9. **旁证（不可引用为观点）** — 同作者其他视频、推荐流条目，单独隔离。

## 4. 引用与改写规则

- 原文引用 ≤150 字/段，用引用块；超出则拆段或改写为 `【归纳】`。
- 不照搬整段口播；`【归纳】` 必须用自己的话重写骨架。
- 不把作者的个人观点写成事实背书；保留「作者声明：个人观点，仅供参考」类信息。
- 不引入视频外的第三方数据来「补全」论证；确需补充时放在「边界与风险」并注明外部来源。
- 涉及价格、库存、优惠、对外承诺、投放预算等经营决策时，笔记只记录方法，不替用户下结论。

## 5. 章节型笔记（以官方章节要点与作者文案为依据）

当文字来源为「N 条官方章节要点 + 官方总摘要 + 作者发布文案」、未使用口播逐字稿时，**交付物仍是一份完整、可直接使用的正式精选笔记**：

- 在「来源与证据」如实写明本次使用的文字来源（官方章节 N 条 + 总摘要 + 作者文案），并说明未使用口播逐字稿、因此不出现 `【原文】` 级引用。**禁止**在顶部放「未完成 / 缺口 / 不覆盖视频全部内容」这类自贬横幅——证据来源不同不等于交付残缺。
- 「核心要点」按主题合并章节，允许把多条章节归纳成一条要点；每条注明依据的章节序号，不臆造章节 / 文案里没有的操作细节。
- 「可执行清单」照常给出可照做的步骤并标依据章节；「与业务的关联」整体标 `【推断】`。
- 需要更细的口播细节时，在「来源与证据」补一句「以原视频对应时间点为准」；不必把它写成阻塞交付的「缺口」。
- **v1.5 前置条件**：`deliverable=limited_note` 走本节；`full_note` 走完整规格，`source_card` / `blocked` 一律停笔。章节型笔记里禁止出现 `【原文】`（口播逐字稿专属），章节引用统一用 `【平台摘要】` 且只在第三节；核心要点 / 可执行清单用 `【归纳】` / `【文案】` / `【推断】`。
- **v1.6 硬门禁**：入库前必须跑 `scripts/lint_note.py`，`error_count>0` 一律改稿后再传。它会自动核对章节表与逐条原文的时间点 / 标题是否与 `chapters.json` 一致，防止从别的视频复制粘贴造成的事实错误。
- 回报时如实说明证据来源（章节要点 + 总摘要 + 作者文案）即可；**不得**把「未跑口播转写」说成「缺字稿 / 缺口」，也不得把已交付的笔记说成残次品、半成品或「有限笔记」。

## 6. 深度模式（RIA-TV++）

仅当用户明确说「做成 skill / 拆成 skill / 生成能力卡」时启用：

```
阶段0 整体理解   → BOOK_OVERVIEW.md
阶段1 五路提取   → candidates/{framework,principle,case,counter-example,glossary}.md
阶段1.5 三重验证 → verified.md + rejected/   （V1 跨域佐证 ≥2 段 / V2 预测力 / V3 独特性）
阶段2 RIA++ 构造 → <slug>/SKILL.md（R / I / A1 / A2 / E / B 六段齐全）
阶段3 链接       → INDEX.md + GLOSSARY.md
阶段4 压力测试   → <slug>/test-prompts.json（应调用 / 诱饵 / 边界模糊）
阶段5 交付       → DIGEST.md
```

- 每完成一阶段更新 `PIPELINE_STATE.md`，支持断点续跑。
- 通过验证的能力卡可询问是否安装到 `~/.workbuddy/skills/`；不自动安装。
- 深度模式的全部产物按 `references/ima-upload.md` 命名规范一并上传到「抖音视频精选」。
- 与 `doudian-course-distiller`、`doudian-natural-flow-starter` 的分界见 `SKILL.md § 一、目标与边界` 的分界表——判别只看输入粒度：**一条视频 → 本 skill 出笔记**；**一门课/多讲 → course-distiller 出一组 skill**。此处不再重复，避免两处说法分叉。

## 7. 禁止项清单

1. 凭标题、话题或记忆编造视频观点。
2. 把推荐流 / 同作者其他视频 / SEO 摘要当成原文引用。
3. 未取得字段填空、按常识补值、把「约 / 大概」写成确定数字。
4. 把 `【推断】` 混入「核心要点」且不标标记；把 `【平台摘要】` 混进核心要点。
5. 生成不含「来源与证据」节的笔记，或把节名写成「来源与缺口」。
6. 把笔记写进「电商」或其他知识库（目标固定为独立知识库 `YOUR_IMA_KB_ID` 根目录，**不传** `folder_id`）。
7. **只查 `chapter_list` 一个键就写「章节要点未取得」**；或 `chapters.json` 已有 N 条，笔记 / 元信息 / STATUS 却把章节要点列为缺口。
8. 把「未取得」当作可以反复复制的惯性结论：每次都要先跑 `extract_chapters.py`，把 `checked_paths` 作为判定依据。
